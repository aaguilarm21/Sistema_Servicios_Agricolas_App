CASOS DE USO DEL SISTEMA
========================
Proyecto: Sistema de Servicios Agrícolas
Fecha: 2026-08-09

1. Nombre del sistema
Sistema de gestión para la administración de usuarios, catálogos, registros operativos y reportes de servicios agrícolas.

2. Actores
- Administrador: gestiona usuarios, catálogos, registros y permisos del sistema.
- Usuario operativo: registra y consulta operaciones agrícolas y logísticas.
- Usuario autenticado: accede a módulos generales del sistema.
- Sistema: valida autenticación, permisos y almacenamiento de información.

3. Casos de uso por funcionalidad

CU-01: Iniciar sesión
- Actor: Usuario autenticado o visitante
- Objetivo: acceder al sistema con credenciales válidas.
- Precondiciones: El usuario debe tener un registro activo en el sistema.
- Flujo principal:
  1. El usuario ingresa su nombre de usuario y contraseña.
  2. El sistema valida las credenciales.
  3. Si son correctas, el sistema autentica al usuario y muestra el panel principal.
- Flujo alternativo:
  1. Si las credenciales son incorrectas, el sistema muestra un mensaje de error.
- Postcondiciones: El usuario queda autenticado y puede acceder a los módulos permitidos.

CU-02: Cambiar de usuario
- Actor: Usuario autenticado
- Objetivo: iniciar sesión con otro usuario desde el panel principal.
- Precondiciones: El usuario debe estar autenticado en el sistema.
- Flujo principal:
  1. El usuario abre el modal de cambio de usuario.
  2. Ingresa las credenciales del nuevo usuario.
  3. El sistema valida la información y cambia la sesión activa.
- Flujo alternativo:
  1. Si las credenciales no son válidas, el sistema muestra un mensaje de error.
- Postcondiciones: La sesión activa cambia al nuevo usuario.

CU-03: Cerrar sesión
- Actor: Usuario autenticado
- Objetivo: finalizar la sesión activa.
- Precondiciones: El usuario debe haber iniciado sesión.
- Flujo principal:
  1. El usuario selecciona la opción cerrar sesión.
  2. El sistema finaliza la sesión y elimina la autenticación activa.
- Postcondiciones: El usuario vuelve a la pantalla de acceso.

CU-04: Registrar usuario
- Actor: Administrador
- Objetivo: crear un nuevo usuario en el sistema.
- Precondiciones: El administrador debe estar autenticado.
- Flujo principal:
  1. El administrador accede al módulo de usuarios.
  2. Ingresa los datos del nuevo usuario y su rol.
  3. El sistema valida que no exista duplicidad.
  4. Se crea el usuario y se asigna el perfil correspondiente.
- Flujo alternativo:
  1. Si el nombre de usuario ya existe, el sistema muestra un mensaje de error.
- Postcondiciones: El nuevo usuario queda registrado y puede iniciar sesión.

CU-05: Activar, desactivar o eliminar usuario
- Actor: Administrador
- Objetivo: modificar el estado de un usuario existente.
- Precondiciones: El administrador debe tener permisos de administración.
- Flujo principal:
  1. El administrador selecciona un usuario.
  2. Elige entre activar, desactivar o eliminar.
  3. El sistema actualiza el estado del usuario o lo elimina.
- Flujo alternativo:
  1. Si el usuario es administrador, el sistema impide bloquearlo.
- Postcondiciones: El estado del usuario queda actualizado.

CU-06: Registrar proveedor
- Actor: Administrador
- Objetivo: almacenar información de un nuevo proveedor.
- Precondiciones: El administrador debe estar autenticado.
- Flujo principal:
  1. El administrador accede a la gestión de proveedores.
  2. Ingresa los datos obligatorios como código, NIT, razón social y datos tributarios.
  3. El sistema valida la información.
  4. Se guarda el proveedor en la base de datos.
- Flujo alternativo:
  1. Si faltan datos obligatorios, el sistema muestra un mensaje de error.
- Postcondiciones: El proveedor queda disponible para futuras operaciones.

CU-07: Editar proveedor
- Actor: Administrador
- Objetivo: modificar la información de un proveedor existente.
- Precondiciones: El proveedor debe existir en el sistema.
- Flujo principal:
  1. El administrador selecciona un proveedor.
  2. Actualiza los datos requeridos.
  3. El sistema guarda los cambios.
- Postcondiciones: La información del proveedor queda actualizada.

CU-08: Eliminar proveedor
- Actor: Administrador
- Objetivo: remover un proveedor del sistema.
- Precondiciones: El proveedor debe existir.
- Flujo principal:
  1. El administrador selecciona el proveedor.
  2. Confirma la eliminación.
  3. El sistema elimina el registro.
- Postcondiciones: El proveedor ya no aparece en el sistema.

CU-09: Registrar empleado
- Actor: Administrador
- Objetivo: guardar información de un empleado.
- Precondiciones: El administrador debe estar autenticado.
- Flujo principal:
  1. El administrador ingresa los datos del empleado.
  2. El sistema valida los campos obligatorios.
  3. Se almacena el empleado correctamente.
- Postcondiciones: El empleado queda registrado en el catálogo.

CU-10: Editar o eliminar empleado
- Actor: Administrador
- Objetivo: modificar o remover datos de un empleado existente.
- Precondiciones: El empleado debe existir.
- Flujo principal:
  1. El administrador selecciona el empleado.
  2. Realiza la edición o confirma la eliminación.
  3. El sistema guarda o elimina el registro.
- Postcondiciones: La información del empleado queda actualizada o eliminada.

CU-11: Registrar maquinaria
- Actor: Administrador
- Objetivo: registrar una nueva máquina o equipo.
- Precondiciones: El administrador debe estar autenticado.
- Flujo principal:
  1. El administrador ingresa los datos de la maquinaria.
  2. El sistema valida los campos obligatorios.
  3. Se guarda la maquinaria en la base de datos.
- Postcondiciones: La maquinaria queda disponible para su uso en operaciones.

CU-12: Registrar bodega
- Actor: Administrador
- Objetivo: registrar una nueva bodega o almacén.
- Precondiciones: El administrador debe estar autenticado.
- Flujo principal:
  1. El administrador ingresa el código, nombre, unidad de medida y capacidad.
  2. El sistema valida los datos.
  3. Se guarda la bodega.
- Postcondiciones: La bodega queda disponible para el control de inventario.

CU-13: Registrar artículo
- Actor: Administrador
- Objetivo: registrar un nuevo artículo o producto.
- Precondiciones: El administrador debe estar autenticado.
- Flujo principal:
  1. El administrador ingresa código, descripción, unidad de medida, categoría y stock.
  2. El sistema valida los datos.
  3. El artículo queda registrado.
- Postcondiciones: El artículo queda disponible para su gestión posterior.

CU-14: Registrar registro operativo
- Actor: Usuario operativo
- Objetivo: registrar una operación agrícola o logística.
- Precondiciones: El usuario debe estar autenticado.
- Flujo principal:
  1. El usuario ingresa los datos de la operación como boleta, fecha, proveedor, máquina, finca, lote, actividad, labor y costos.
  2. El sistema valida los campos obligatorios.
  3. Se almacena el registro operativo.
  4. El sistema muestra una confirmación.
- Flujo alternativo:
  1. Si faltan datos obligatorios, el sistema muestra un mensaje de error.
- Postcondiciones: El registro operativo queda guardado en la base de datos.

CU-15: Editar o eliminar registro operativo
- Actor: Usuario operativo o Administrador
- Objetivo: modificar o quitar un registro previamente guardado.
- Precondiciones: El registro debe existir.
- Flujo principal:
  1. El usuario selecciona un registro operativo.
  2. Realiza la edición o confirma la eliminación.
  3. El sistema actualiza o elimina el registro.
- Postcondiciones: El registro queda actualizado o eliminado.

CU-16: Administrar catálogos auxiliares
- Actor: Administrador
- Objetivo: mantener información de apoyo del sistema.
- Precondiciones: El administrador debe estar autenticado.
- Flujo principal:
  1. El administrador accede a la configuración de catálogos.
  2. Registra o modifica elementos como labores, cuentas, unidades de medida, variedades, tipos de máquina, marcas, municipios o auxiliares.
  3. El sistema guarda los cambios.
- Postcondiciones: Los catálogos quedan disponibles para el registro de operaciones.

CU-17: Buscar información por código
- Actor: Usuario autenticado
- Objetivo: consultar información de usuarios o empleados para completar formularios.
- Precondiciones: Debe existir información registrada.
- Flujo principal:
  1. El usuario ingresa un código en el formulario.
  2. El sistema busca coincidencias.
  3. Muestra los datos relacionados.
- Postcondiciones: El usuario obtiene información útil para completar el proceso.

CU-18: Generar reporte
- Actor: Usuario o Administrador
- Objetivo: consultar indicadores y reportes de las operaciones registradas.
- Precondiciones: Deben existir registros operativos en el sistema.
- Flujo principal:
  1. El usuario selecciona filtros como fecha, proveedor o tipo de servicio.
  2. El sistema consulta la información.
  3. Muestra el reporte correspondiente.
- Postcondiciones: El usuario obtiene una vista resumida de la información.

4. Resumen general
El sistema permite al administrador gestionar usuarios, proveedores, empleados, inventarios, catálogos y registros operativos, mientras que los usuarios operativos pueden registrar operaciones y consultar información relevante para la gestión agrícola.
